**DrCortex** (`dcx`) یک فریم‌ورک سبک، بدون وابستگی خارجی و مستقل از مدل برای مدیریت تیم ایجنت‌های برنامه‌نویسی در محیط‌های توسعهٔ هوش مصنوعی مانند **Antigravity IDE**، **Claude Code**، **OpenCode** و **Codex** است.

به جای اینکه دستیار هوش مصنوعی بدون برنامه فایل‌ها را تغییر دهد یا سهمیهٔ مدل‌های قدرتمند را روی کارهای تکراری هدر دهد، DrCortex اجرای پروژه را در قالب یک **تیم ۹ نفرهٔ مهندسی** با یک نقطهٔ تماس واحد (**`@Envoy`**)، کشف عمیق بدون ابهام توسط **`@Researcher`**، نظارت دروازه‌های انسانی توسط **`@Gatekeeper`**، **چرخهٔ ۵ دروازه‌ای با تأیید انسان**، **Skill Finder داخلی** و **ترمزهای اضطراری بیلد** سازمان‌دهی می‌کند.

## ✨ چرا DrCortex؟

- **یک نقطهٔ تماس واحد (`@Envoy`):** شما فقط با یک ایجنت در چت صحبت می‌کنید. `@Envoy` در پشت صحنه با `@Researcher`، `@Lead`، `@Architect`، `@Gatekeeper`، `@Backend`، `@Frontend`، `@Reviewer`، `@Ops` و ایجنت‌های سفارشی پروژه هماهنگ می‌شود.
- **کشف عمیق بدون ابهام (`@Researcher`):** قبل از طراحی معماری هر فیچر جدید، `@Researcher` از طریق `@Envoy` آن‌قدر سؤال شفاف‌ساز می‌پرسد تا هیچ ابهامی باقی نماند.
- **ممیزی دروازه‌های انسانی (`@Gatekeeper`):** ناظر اختصاصی که از دور زدن دروازه‌های تأیید جلوگیری کرده و پیش‌نیازهای ورود و خروج هر دروازه را کنترل می‌کند.
- **Skill Finder داخلی و ایگنور همیشگی `agent/skills/`:** اسکیل‌های متناسب با استک پروژه (حتی استک‌های دستی) را در `agent/skills/` می‌سازد و این پوشه را **همیشه** در `.git/info/exclude` مخفی نگه می‌دارد.
- **افزودن ایجنت سفارشی (`dcx agent add`):** می‌توانید ایجنت‌های اختصاصی پروژه را در `agent/agents/` اضافه کنید تا `@Envoy` به‌صورت خودکار از آن‌ها استفاده کند.
- **لایه‌بندی پویای مدل‌ها (۱ تا ۴ مدل):** هنگام نصب، مدل‌های خود را از قوی‌ترین تا سریع‌ترین مرتب می‌کنید. کارهای ساده خودکار به مدل‌های سبک‌تر می‌روند و با رسیدن مصرف سهمیه به بالای ۸۰٪، حالت **`ECO_MODE`** فعال می‌شود.
- **روت تمیز پروژه و مهاجرت امن:** در ریشهٔ پروژه فقط `AGENT.md`، `agent/` و `reports/` ساخته می‌شود. اگر قبلاً `CLAUDE.md`، `.cursorrules` یا `AGENT.md` داشته باشید، بکاپ گرفته و قوانین قبلی را ادغام می‌کند.
- **سازگار با لینوکس، مک و ویندوز:** فقط با کتابخانهٔ استاندارد Python 3 نوشته شده و نیازی به نصب هیچ پکیج اضافه‌ای ندارد.

## 🏗️ معماری و نقش ایجنت‌ها

```text
کاربر ──▶ @Envoy (نقطه تماس واحد)
            ├── @Researcher ──▶ کشف عمیق نیازمندی‌ها؛ پرسش تا رفع کامل ابهام
            ├── @Lead       ──▶ تحلیل نیازمندی‌ها و کشف حالات لبه (Edge Cases)
            ├── @Architect  ──▶ طراحی سیستم، اسکیمای دیتابیس و api-contract.yaml
            ├── @Gatekeeper ──▶ ناظر دروازه‌های انسانی؛ کنترل توقف‌های اجباری و تأییدیه‌ها
            ├── @Reviewer   ──▶ ممیزی امنیت، جلوگیری از N+1، تایپ‌سیفتی و نوشتن تست
            ├── @Backend    ──▶ منطق سمت سرور، سرویس‌ها، ریپازیتوری‌ها و جاب‌ها
            ├── @Frontend   ──▶ کامپوننت‌های UI، مدیریت state و اتصال به API
            ├── @Ops        ──▶ اجرای بیلد و تست، داکر/CI و گزارش نهایی مرحله
            └── agent/agents/*.md ──▶ ایجنت‌های سفارشی ساخته‌شده با `dcx agent add`
```

| نقش | لایه پیش‌فرض | مسئولیت |
| :--- | :--- | :--- |
| **`@Envoy`** | لایه ۱ (پرچم‌دار) | ارتباط با کاربر، جمع‌بندی، اجرای workflow و پایش سهمیه |
| **`@Researcher`** | لایه ۱ (پرچم‌دار) | کشف عمیق و پرسش متوالی از طریق `@Envoy` تا رسیدن به ابهام صفر |
| **`@Lead`** | لایه ۱ (پرچم‌دار) | تحلیل نیازمندی‌ها و شکستن تسک‌ها |
| **`@Architect`** | لایه ۱ (پرچم‌دار) | طراحی معماری، دیتابیس و قراردادهای API |
| **`@Gatekeeper`** | لایه ۲ (استدلال بالا) | ناظر دروازه‌های انسانی: کنترل توقف‌های اجباری و معیارهای خروج |
| **`@Reviewer`** | لایه ۱ (پرچم‌دار) | دروازه‌بان کد: امنیت، تایپینگ، کوئری‌های N+1 و تست‌نویسی |
| **`@Backend`** | لایه ۳ (متعادل) | پیاده‌سازی سرویس‌ها، اندپوینت‌ها و کوئری‌های دیتابیس |
| **`@Frontend`** | لایه ۳ (متعادل) | پیاده‌سازی رابط کاربری و اتصال به قرارداد API |
| **`@Ops`** | لایه ۴ (سریع/اقتصادی) | اجرای بیلد و تست و تولید گزارش پایانی |

## 🚀 آموزش گام‌به‌گام استفاده (از صفر تا اجرا)

برای شروع، این ۵ مرحله را به ترتیب انجام دهید:

### گام ۱: نصب DrCortex

دستور تک‌خطی زیر را متناسب با سیستم‌عامل خود در ترمینال اجرا کنید (نیازی به `git clone` دستی نیست):

**Linux / macOS:**
```bash
curl -fsSL https://raw.githubusercontent.com/DrAmir0240/DrCortex/main/install.sh | bash
```

**Windows (PowerShell):**
```powershell
irm https://raw.githubusercontent.com/DrAmir0240/DrCortex/main/install.ps1 | iex
```

<details>
<summary>روش جایگزین: نصب از کلون محلی</summary>

```bash
git clone https://github.com/DrAmir0240/DrCortex.git
cd DrCortex
./install.sh        # لینوکس و مک
# یا .\install.ps1  # ویندوز پاورشل
```

</details>

> **این دستور چه کاری انجام می‌دهد؟** ابزار را در `~/.drcortex` (در ویندوز `%USERPROFILE%\.drcortex`) نصب می‌کند، دستورات `drcortex` و `dcx` را به `PATH` اضافه می‌کند و بلافاصله ویزارد تنظیمات سراسری (`dcx setup`) را اجرا می‌کند.

---

### گام ۲: ویزارد تنظیمات سراسری (`dcx setup`)

بلافاصله بعد از نصب (یا هر زمان که بخواهید با دستور `dcx setup`)، ویزارد این موارد را از شما می‌پرسد:

1. **انتخاب محیط کدنویسی هوش مصنوعی:**
   - `[1]` **Antigravity IDE** (`~/.gemini/antigravity/GEMINI.md`)
   - `[2]` **Claude Code** (`~/.claude/CLAUDE.md`)
   - `[3]` **Universal / OpenCode / Codex** (`~/.config/drcortex/GLOBAL_RULES.md`)
   - `[4]` **مسیر دلخواه** (وارد کردن مسیر دستی فایل قوانین)
2. **تعداد مدل‌های در دسترس (`1` تا `4`).**
3. **نام مدل‌ها از قوی‌ترین به سبک‌ترین** (لایه ۱ پرچم‌دار تا لایه ۴ سریع/اقتصادی).

تنظیمات در `~/.drcortex/config.json` ذخیره و فایل قوانین سراسری IDE شما به‌صورت خودکار ساخته می‌شود.

### گام ۳: مقداردهی اولیه در پروژه (`dcx init`)

وارد پوشهٔ اصلی (روت) پروژهٔ خود شوید و اجرا کنید:

```bash
cd /path/to/your-project
dcx init
```

در این مرحله ۳ سؤال از شما پرسیده می‌شود:

1. **مدیریت فایل‌های قبلی (در صورت وجود):** اگر فایل‌هایی مثل `AGENT.md`، `CLAUDE.md`، `.cursorrules`، `agent/` یا `reports/` در پروژه باشد، یکی از این گزینه‌ها را انتخاب می‌کنید:
   - `[1]` **Migrate & Merge** — از فایل‌های قبلی در `agent/.internal/backup-legacy/<timestamp>/` بکاپ می‌گیرد، پوشه‌های step را نگه می‌دارد و قوانین قبلی را به انتهای `agent/development-policy.md` اضافه می‌کند.
   - `[2]` **Coexist** — به فایل‌های فعلی دست نمی‌زند و فقط فایل‌های کمبود DrCortex را اضافه می‌کند.
   - `[3]` **Fresh Overwrite** — بکاپ می‌گیرد و قالب‌های تمیز DrCortex را جایگزین می‌کند.
2. **انتخاب استک پروژه و نصب خودکار اسکیل‌ها:**
   - `[1]` `python-nextjs` (فول‌استک: FastAPI/Django + Next.js/TypeScript)
   - `[2]` `python-only` (بک‌اند پایتون)
   - `[3]` `generic` (عمومی، مستقل از زبان)
   - `[4]` `custom` — وارد کردن استک دلخواه به‌صورت دستی (مثل `Go + React + PostgreSQL`). Skill Finder اسکیل‌های پیش‌فرض آن استک را در `agent/skills/` می‌سازد.
3. **ردیابی در Git:**
   - **`Y`**: فایل‌های `AGENT.md`، `agent/` و `reports/` در گیت پروژه ثبت می‌شوند (اما `agent/skills/` **همیشه** در `.git/info/exclude` مخفی می‌ماند).
   - **`n`**: کل فایل‌های DrCortex از طریق `.git/info/exclude` فقط روی سیستم شما مخفی می‌شوند (بدون دست زدن به `.gitignore`).

> **اجرای سریع بدون پرسش (Non-interactive):**
> ```bash
> dcx init --stack custom --custom-stack "Go + React + PostgreSQL" --git track
> ```

### گام ۴: توسعهٔ فیچر با چرخهٔ ۵ دروازه‌ای

حالا چت هوش مصنوعی IDE خود را در پروژه باز کنید و مستقیم درخواست خود را بنویسید (تگ کردن `@Envoy` اختیاری است — چت به‌صورت پیش‌فرض همیشه با `@Envoy` است):

```text
می‌خواهم اولین فیچر را بسازیم: [توضیح فیچر یا باگی که می‌خواهید بسازید]
```

از این لحظه هر فیچر یا باگ‌فیکس دقیقاً از این **۵ دروازه (Gate)** عبور می‌کند:

1. **دروازه ۱ — کشف عمیق و پیشنهاد بهترین معماری (توقف اجباری):**
   `@Researcher` از طریق `@Envoy` آن‌قدر سؤال شفاف‌ساز می‌پرسد تا **هیچ ابهامی باقی نماند**. سپس `@Lead` و `@Architect` بهترین راهکار را طراحی می‌کنند و `@Gatekeeper` تا زمان تأیید صریح شما متوقف می‌ماند.
2. **دروازه ۲ — مستندسازی مرحله (توقف اجباری):**
   بعد از تأیید دروازه ۱، پوشهٔ `agent/01-step-<slug>/` همراه با `instructions.md` و `tasks.md` ساخته می‌شود. `@Envoy` خلاصهٔ برنامه را نشان می‌دهد و `@Gatekeeper` تا قبل از تأیید شما اجازهٔ نوشتن کد نمی‌دهد.
3. **دروازه ۳ — اجرای موازی و کنترل کیفیت خودکار:**
   `@Reviewer` در صورت نیاز اول تست‌های شکست‌خورنده را می‌نویسد؛ `@Backend`، `@Frontend` و ایجنت‌های سفارشی هم‌زمان پیاده‌سازی می‌کنند و بلافاصله تیک `[x]` هر زیرتسک را در `tasks.md` می‌زنند؛ در پایان `@Reviewer` ممیزی کد و `@Ops` بیلد و تست‌ها را اجرا می‌کند.
4. **دروازه ۴ — تأییدیهٔ Gatekeeper و تست دستی کاربر (UAT):**
   `@Gatekeeper` بررسی می‌کند که همهٔ چک‌لیست‌ها و تست‌ها پاس شده باشند، سپس `@Envoy` لیست فایل‌های تغییریافته را اعلام کرده و پروژه را برای تست دستی تحویل می‌دهد.
5. **دروازه ۵ — حلقهٔ بازخورد یا بستن مرحله:**
   - اگر ایراد یا تغییری دارید به `@Envoy` می‌گویید تا به دروازه ۳ برگردد.
   - اگر همه‌چیز تایید شد، `@Gatekeeper` تأیید نهایی را ثبت می‌کند، `@Ops` گزارش نهایی را در `reports/01-<slug>.md` می‌سازد و `@Envoy` وضعیت مرحله را در `agent/.internal/BOARD.md` روی `DONE` قرار می‌دهد.

### گام ۵: مدیریت اسکیل‌ها، ایجنت‌های سفارشی، Git و وضعیت

هر زمان خواستید می‌توانید اسکیل جدید یا ایجنت جدید اضافه کنید یا ردیابی Git را تغییر دهید:

```bash
dcx skill list                  # لیست اسکیل‌های نصب‌شده در agent/skills/
dcx skill find rust             # جستجو در کاتالوگ Skill Finder
dcx skill add docker-devops     # افزودن اسکیل به agent/skills/ (همیشه git-excluded)
dcx agent list                  # لیست ۹ ایجنت داخلی + ایجنت‌های سفارشی همراه با وضعیت
dcx agent add                   # ساخت ایجنت سفارشی جدید در agent/agents/
dcx agent disable Gatekeeper    # خاموش کردن یک ایجنت (ثبت در agent/.internal/BOARD.md)
dcx agent enable Gatekeeper     # روشن کردن مجدد یک ایجنت
dcx status                      # نمایش وضعیت مدل‌ها، اسکیل‌ها و ایجنت‌ها
dcx git ignore                  # مخفی کردن فایل‌های DrCortex در .git/info/exclude
dcx git track                   # ردیابی AGENT.md، agent/ و reports/ (agent/skills/ مخفی می‌ماند)
```

## 🛠️ مرجع دستورات CLI

| دستور | آرگومان‌ها / فلگ‌ها | توضیح |
| :--- | :--- | :--- |
| `dcx setup` | — | اجرای ویزارد تنظیمات سراسری IDE و سلسله‌مراتب ۴ لایه مدل‌ها |
| `dcx init` | `--stack {python-nextjs,python-only,generic,custom}`<br>`--custom-stack "..."`<br>`--git {track,ignore}`<br>`--mode {migrate,coexist,overwrite}` | مقداردهی اولیهٔ DrCortex، نصب اسکیل‌های استک و تنظیم Git |
| `dcx skill` | `list` \| `find <query>` \| `add <name>` | جستجو و مدیریت اسکیل‌ها در `agent/skills/` (همیشه git-excluded) |
| `dcx agent` | `list` \| `add [--name --tier --role --triggers]` \| `enable <name>` \| `disable <name>` | نمایش، افزودن، روشن یا خاموش کردن ایجنت‌های داخلی و سفارشی |
| `dcx git` | `track` \| `ignore` | فعال یا غیرفعال کردن ردیابی فایل‌های DrCortex در Git از طریق `.git/info/exclude` |
| `dcx status` | — | نمایش تنظیمات سراسری مدل‌ها و وضعیت پروژهٔ محلی |

*(هر دو دستور `drcortex` و `dcx` به یک فایل اجرایی اشاره می‌کنند.)*

## 📁 ساختار فایل‌ها در پروژه

پس از اجرای `dcx init`، روت پروژهٔ شما کاملاً تمیز و فقط شامل این ۳ بخش است:

```text
your-project/
├── AGENT.md                          # قوانین ورودی ایجنت‌ها در پروژه
├── agent/
│   ├── development-policy.md         # استانداردهای معماری، امنیت و دستورات تست پروژه
│   ├── .internal/
│   │   ├── BOARD.md                  # وضعیت مرحله فعال، دروازه فعلی، سهمیه و تاریخچه
│   │   └── step-template/
│   │       ├── instructions.md       # قالب سند فنی هر مرحله
│   │       └── tasks.md              # قالب چک‌لیست اجرای مرحله
│   └── 01-step-<slug>/               # ساخته می‌شود در دروازه ۲ برای هر فیچر/باگ
└── reports/
    ├── 00-report-template.md
```

## 🛡️ قوانین ایمنی و ترمزهای اضطراری

- **قانون حداکثر ۲ تلاش بیلد (Max 2-Strike Build Rule):** حداکثر ۲ بار تلاش برای بیلد/تست مجاز است. اگر بار دوم هم خطا داد، اجرا فوراً متوقف می‌شود (`HALTED_ON_BUILD_ERROR`) و `@Envoy` علت ریشه‌ای و ۲ راه‌حل پیشنهادی را گزارش می‌دهد.
- **سیاست بدون حدس‌زدن (Zero-Guessing Policy):** در صورت ابهام در نیازمندی‌ها، کار متوقف (`BLOCKED_ON_USER`) و از کاربر سؤال پرسیده می‌شود.
- **محدودیت تغییرات اتمیک:** در هر نوبت حداکثر ۳ تا ۵ فایل تغییر داده می‌شود (مگر در تغییر نام سراسری).
- **استانداردهای کدنویسی:** جداسازی ۳ لایه (`Router -> Service -> Repository`)، تایپینگ سخت‌گیرانه (ممنوعیت `any`)، جلوگیری از کوئری‌های N+1، تغییر اسکیما فقط با Migration، ممنوعیت hardcode کردن Secretها و کنترل دسترسی سمت سرور (RBAC/IDOR).
